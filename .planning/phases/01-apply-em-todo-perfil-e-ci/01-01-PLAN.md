```text
Env (all optional):
  SOURCE_ROOT      repo root to validate (default: parent dir of ci/)
  CI_PROFILES_DIR  fixtures dir (default: $SOURCE_ROOT/ci/profiles)
  CI_TOOLS_DIR     tool dir, prepended to PATH when it exists (default: ${TMPDIR:-/tmp}/dotfiles-ci-tools)
  CI_BASE_CONFIG   reuse an existing base config instead of regenerating it
  CI_FORCE_PINNED  =1 → bootstrap always installs pinned versions (set in the workflow)
  CI_KEEP_WORK     =1 → keep the temp work dir and print its path

Exit codes: 0 ok · 1 render/shellcheck/drift failures · 2 usage error, D-09 violation, or --only matched nothing

Output lines (exact prefixes; tests grep for them):
  RENDERED [<profile>] <source path relative to SOURCE_ROOT>        (only with --list)
  RENDER FAIL [<profile>] <source path>: <first stderr line of chezmoi>
  SHELLCHECK [<profile>] <source path>: <gcc-format finding incl. SCxxxx>
  DRIFT [<profile>] missing <section>.<key>
  PROFILE <profile>: rendered=<N> render_failures=<X> shellchecked=<M> shellcheck_failures=<Y> drift=<D>
  GATE OK | GATE FAILED
  TOOL <name> <version> <path>                                       (bootstrap-tools.sh, one per tool)
  COMPOSE OK <stack> | COMPOSE FAIL <stack>: <first error line>
  COMPOSE OK (stacks=<N>) | COMPOSE FAILED (failed=<N>)
```

chezmoi invocation (every call in render.sh):
`chezmoi --config "$BASE" --persistent-state "$WORK/state.boltdb" --cache "$WORK/cache" --source "$SOURCE_ROOT" --destination "$WORK/dest" --no-tty --override-data-file "$CI_PROFILES_DIR/$PROFILE.yaml" [--override-data "$OVERRIDE_JSON"] execute-template < "$STUBBED_COPY"`.
The base config `$BASE` is produced by `CHEZMOI_SKIP_SHELL_PROBES=1 chezmoi --persistent-state "$WORK/state.boltdb" --source "$SOURCE_ROOT" execute-template --init --stdinisatty=false < "$SOURCE_ROOT/home/.chezmoi.yaml.tmpl"`. A failure there is reported as `RENDER FAIL [config] home/.chezmoi.yaml.tmpl: …` and fails the gate.

Decrypt stub (applied with `sed -E` to a CR-stripped temp copy of each candidate, never to the original, never to an `encrypted_*` file):
`s/(joinPath[^|}]*[|][[:space:]]*include|include[[:space:]]+[^|}]+)[[:space:]]*[|][[:space:]]*decrypt/"ci-placeholder-secret"/g`
After stubbing, if the copy still contains the word `decrypt` (`grep -qw decrypt`), abort with `D-09: decrypt survived stubbing in <source path>` and exit 2.

Candidate discovery (gate): `find "$SOURCE_ROOT/home" -type f -name '*.tmpl'`, pruning any path containing `/encrypted_`, and excluding `home/.chezmoitemplates/**`, `home/.chezmoidata/**`, `home/.chezmoi.yaml.tmpl`, `home/.chezmoiignore.tmpl`. If any surviving candidate path contains `encrypted_`, exit 2 (defensive D-09 check). `home/.chezmoiexternals/*.tmpl` are rendered in every profile without ignore filtering (they are config, not targets). Every other candidate is mapped with one `chezmoi target-path` call (paired by order), the destination root printed by `chezmoi target-path` with no args is stripped, and the relative target is kept unless it matches an ignore pattern. `--only SUBSTR` (repeatable) keeps only candidates whose source path contains one of the substrings.

Ignore matching: render `home/.chezmoiignore.tmpl` with the profile and strip `\r`. Trim each line; skip blank lines and lines starting with `#`. A line starting with `!` aborts with exit 2 ("negated ignore patterns not supported by ci/render.sh"). A target `t` is ignored when `[[ $t == $p || $t == $p/* ]]` for some pattern `p` (unquoted, so `*`/`**` glob; this reproduces chezmoi's results for every pattern in the current file).

Shellcheck scope: rendered outputs whose target starts with `.chezmoiscripts/` and does not end in `.ps1`, plus rendered targets ending in `.sh`; skip whitespace-only outputs. Command: `"$SHELLCHECK" --shell=bash --severity=warning --format=gcc <file>` (SHELLCHECK defaults to `shellcheck`).

Drift: for each profile compare `{{ keys .settings | sortAlpha | join "\n" }}` (same for `.dirs`, `.features`, `.gpg`) rendered with `--config "$BASE"` against the same rendered with an empty config plus `--override-data-file` fixture. Any key in the first list and not the second is a `DRIFT` line. The gate runs drift first for the selected profiles.
