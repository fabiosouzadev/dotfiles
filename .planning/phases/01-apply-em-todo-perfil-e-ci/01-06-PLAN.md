## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository settings → runner | enabling Actions lets workflow code run on Codeberg or self-hosted infrastructure with an auto-generated repository token |
| public CI logs → anyone | logs of a public repository's runs are world-readable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-19 | Elevation of Privilege | Actions enabled with auto token | medium | mitigate | the workflow uses no `secrets.*` and never uses the auto token; the checkpoint instructs to add no secret or key (D-09) |
| T-01-20 | Information Disclosure | public run logs | low | mitigate | logs only show source paths, PASS/FAIL lines and the literal placeholder; decrypt is stubbed and no encrypted file is read (D-09, plan 01-01) |
| T-01-21 | Elevation of Privilege | Plan B self-hosted runner | medium | mitigate | docs (plan 01-04) recommend a machine other than the production VPS; the label switch is the only workflow change |
| T-01-SC | Tampering | package installs | high | mitigate | no installs in this plan |
</threat_model>
